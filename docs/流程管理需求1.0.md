# 流程管理需求 1.0

## 1. 项目背景

在 MeshCentral 管理系统中集成流程管理功能，旨在提供一个统一的入口，对管理控制台中已有的 3 个自动化流程进行增删改查管理，并支持通过 MeshCentral 的 Agent 能力对指定设备远程执行流程内的脚本和命令。

**与采集管理的关系**：流程管理与采集管理是并列的功能模块。商品发布流程（publish）和调价流程（pricing）在执行时，依赖采集管理预先从美团外卖 H5 采集并存入数据库的数据；若数据库中无对应有效采集数据，则不允许触发这两个流程的同步执行（执行按钮禁用）。自动回复监控流程（auto_reply）无此依赖，可直接执行。

当前 3 个流程来自 `aibot/web/index.html`（管理控制台），分别为：

| 流程 ID | 流程名称 | 说明 |
| --- | --- | --- |
| `publish` | 商品发布流程 | 读取采集管理已采集的店铺商品数据，同步发布到美团商家后台 |
| `pricing` | 调价流程 | 读取采集管理已采集的竞品价格数据，自动对目标商品改价 |
| `auto_reply` | 自动回复监控流程 | 常驻监控美团 IM 工作台并自动回复买家消息 |

## 2. 界面设计要求

- **风格参考**：与店铺管理、商品管理页面保持一致，采用与 MeshCentral 管理后台相协调的克制风格。
- **视觉特点**：
  - 采用卡片式布局展示流程列表。
  - 响应式设计，优先适配桌面端浏览器，兼顾移动端。
  - 图标使用简洁明快的风格。

## 3. 功能需求

### 3.1 流程列表 (Read)

- 展示所有已保存到数据库的流程记录。
- 每条记录卡片展示：流程名称、流程类型（publish / pricing / auto_reply）、目标设备、目标设备系统（macOS / Windows）、当前平台脚本入口、上次执行时间、执行状态。
- 支持按流程名称模糊搜索。
- 流程数量较多时支持分页展示（每页默认 10 条）。
- 列表为空时展示友好的空状态提示（如"暂无流程，点击右上角添加"）。
- 每条记录提供**编辑**、**删除**和**执行**三个操作按钮；对于 `auto_reply` 且处于运行中的流程，额外提供**停止**按钮。

### 3.2 添加流程 (Create)

- 提供"新增流程"按钮（页面右上角）。
- 输入项：
  - **流程名称**：用户自定义名称，必填。
  - **流程类型**：下拉选择 `publish`（商品发布）/ `pricing`（调价）/ `auto_reply`（自动回复），必填。
  - **目标设备**：选择已在 MeshCentral 注册的设备（Agent），必填；系统根据设备信息识别目标系统类型（macOS / Windows），无法识别时需人工选择。
  - **脚本入口配置**：系统按流程类型提供默认跨平台脚本入口，允许管理员调整。macOS 使用 `scripts-mac/*.sh`，Windows 使用 `scripts/*.ps1`，具体默认值见第 8 节。
  - **流程配置（JSON）**：对应流程类型的完整配置内容（见第 4 节），选填，留空时使用默认配置。
  - **备注**：选填。
- 提交校验：流程名称、流程类型、目标设备、目标设备系统、对应平台脚本入口为必填，其余选填。
- 提交成功/失败后展示 Toast 轻提示。

### 3.3 编辑流程 (Update)

- 列表卡片操作区提供"编辑"按钮，点击后弹出全屏或居中弹窗表单进行修改。
- 编辑弹窗复用新增表单，字段预填入当前流程数据。
- 流程配置（JSON）以可编辑文本域展示，支持直接修改。
- 保存成功/失败后展示 Toast 轻提示。

### 3.4 删除流程 (Delete)

- 列表卡片操作区提供"删除"按钮（与编辑按钮并列）。
- 点击删除后弹出确认弹窗，防止误操作。
- 确认删除后列表自动刷新，并展示 Toast 轻提示。

### 3.5 执行流程

- 每条流程记录提供"执行"按钮。
- **前置数据检查**（仅 publish 和 pricing 流程）：点击"执行"前，系统自动检查对应数据表中是否存在有效采集数据。publish 流程检查 `collect_results` 表中是否存在类型为 `collect_shop`、状态为 `success` 且 `syncStatus=success` 的采集结果，并确认对应标准化商品数据已同步到 `meituan_h5_products`；pricing 流程检查 `collect_results` 表中是否存在类型为 `collect_price` 且状态为 `success` 的有效采集数据（默认有效期 1 周）。若无有效数据，"执行"按钮禁用，并展示提示（如"请先在采集管理中完成店铺信息采集"/ "请先在采集管理中完成价格信息采集"）。`auto_reply` 流程无此检查，可直接执行。
- 采集结果匹配优先级需按流程类型区分：
  - `publish`：以 `products[]` 中每个商品项自己的绑定配置为准。单个商品若配置了 `collectResultId`，则读取指定结果并校验类型、状态和同步状态；否则若配置了 `collectTaskId`，则读取该任务下最新有效结果；若两者都未配置，则按 `shopName + productName` 从最新有效 `collect_shop` 结果对应的 `meituan_h5_products` 中匹配数据。
  - `pricing`：流程记录中若配置了 `collectResultId`，则读取指定结果并校验类型、状态和有效期；否则若配置了 `collectTaskId`，则读取该任务下最新有效结果；若两者都未配置，则按 `collect_price` 读取最新有效结果。推荐 1.0 显式保存 `collectTaskId` 或 `collectResultId`。
- 点击执行后，系统通过 MeshCentral 的 Agent 能力，在已选目标设备上执行对应平台的本地脚本入口和命令。
- 执行触发逻辑：
  1. 读取该流程记录的配置（流程类型、目标设备、目标设备系统、对应平台脚本入口、流程配置 JSON）。
  2. 对于 publish 流程：按商品逐条应用采集结果匹配优先级，定位每个商品项对应的有效 `collect_shop` 结果记录，再读取由这些结果同步到 `meituan_h5_products` 的标准化商品数据作为商品数据源，传入执行脚本。
  3. 对于 pricing 流程：按采集结果匹配优先级从 `collect_results` 读取有效 `collect_price` 数据作为竞品价格参考，传入执行脚本。
  4. MeshCentral 服务端将最终流程配置 JSON 写入目标设备临时配置文件，或上传到目标设备指定临时目录。
  5. 调用 MeshCentral Agent 的命令执行能力，在目标设备上运行与系统匹配的脚本入口，并把临时配置文件路径作为参数传入。
  6. Agent 在目标设备上执行本地 `ai-bot` 仓库中的脚本；脚本内容以目标设备本地文件为准，流程记录保存脚本路径、参数模板和脚本名称，不要求把完整业务脚本内嵌到 MeshCentral。
  7. 执行结果（stdout、stderr、退出码、状态）完成后回传，展示在卡片的执行状态区域；执行记录中写入本次实际使用的 `collectBindings`，便于追溯数据来源。1.0 版本以完成后更新为准，实时日志可作为后续增强。
- 执行 UI 状态可选值：空闲 / 执行中 / 成功 / 失败 / 需人工处理 / 已跳过。
- 执行存储状态可选值：idle / running / success / failed / manual_required / skipped。前端展示时映射为对应中文状态。
- 执行期间"执行"按钮禁用，防止重复触发。

### 3.6 停止常驻流程

- `auto_reply` 处于运行中时，列表卡片提供"停止"按钮。
- 点击"停止"后，系统通过 MeshCentral Agent 向目标设备发送停止命令，优先按运行中的 `sessionId` / `processId` 定位并结束对应进程。
- 停止成功后更新流程当前状态为 `idle` 或 `stopped`，并在 `flow_runs` 中补写 `finishedAt`、停止原因和最后心跳时间。
- 若停止失败，需保留原运行状态并展示错误原因，允许管理员重试停止。

## 4. 流程类型与配置字段说明

### 4.1 商品发布流程（publish）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市，例如"苏州市" |
| `myLocationAddress` | string | 定位地址，例如"相城区黄埭实验小学" |
| `products` | array | 商品条目列表 |
| `products[].key` | string | 商品节点唯一标识，用于图片命名和日志 |
| `products[].shopName` | string | 来源店铺名称 |
| `products[].productName` | string | 来源商品名称或关键词 |
| `products[].collectTaskId` | string | 可选，指定商品发布流程使用的 `collect_shop` 采集任务 ID |
| `products[].collectResultId` | string | 可选，指定商品发布流程使用的 `collect_shop` 采集结果 ID；配置后仍需校验状态、类型和有效期，并基于该结果读取同步到 `meituan_h5_products` 的标准化商品数据 |
| `products[].enabled` | boolean | 是否启用，默认 true |
| `products[].overwritePolicy` | string | 覆盖策略：overwrite / merge / skipIfExists |
| `products[].requiredAttributeMappings` | array | 属性值映射规则，每条含 label、from、to |

- 说明：`publish` 的采集数据绑定粒度为商品项级别，不在流程根级别重复定义 `collectTaskId` / `collectResultId`，避免同一流程内多商品来源不一致时产生歧义。

### 4.2 调价流程（pricing）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市 |
| `myLocationAddress` | string | 定位地址 |
| `globalEnabled` | boolean | 全局开关，是否启用全部调价任务 |
| `collectTaskId` | string | 可选，指定调价流程使用的 `collect_price` 采集任务 ID |
| `collectResultId` | string | 可选，指定调价流程使用的采集结果 ID；配置后仍需校验状态、类型和有效期 |
| `tasks` | array | 调价任务列表 |
| `tasks[].taskId` | string | 任务唯一标识 |
| `tasks[].enabled` | boolean | 任务是否启用 |
| `tasks[].targetProductName` | string | 目标商品名称 |
| `tasks[].referenceKeyword` | string | 参考商品关键词 |
| `tasks[].referenceShops` | array | 参考店铺列表（每行一个店铺名） |
| `tasks[].referenceProductSelection` | string | 参考商品选择：first / lowest / highest / average |
| `tasks[].strategy` | string | 调价策略：average / max / min / fixed |
| `tasks[].priceOffset` | number | 价格偏移量 |
| `tasks[].fixedPrice` | number\|null | 固定价格，空时按策略计算 |
| `tasks[].duplicateTargetPolicy` | string | 重复商品处理：fail / first |
| `tasks[].skuStrategy` | string | SKU 策略：allActive / first / mainOnly |
| `tasks[].priceLimit.min` | number\|null | 最低限价 |
| `tasks[].priceLimit.max` | number\|null | 最高限价 |

### 4.3 自动回复监控流程（auto_reply）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `autoReply.enabled` | boolean | 是否启用监控 |
| `autoReply.replyText` | string | 固定回复文本，例如"您好" |
| `autoReply.pollIntervalSeconds` | number | 轮询间隔（秒），默认 3 |
| `autoReply.maxRetries` | number | 最大重试次数，默认 3 |
| `autoReply.cdpUrl` | string | Chrome CDP 地址，默认 `http://127.0.0.1:9222` |
| `autoReply.preferredUrl` | string | 优先跳转的 IM 工作台页面 URL |
| `autoReply.fallbackOpenUrl` | string | 备用打开地址 |
| `autoReply.monitorRecentContacts` | boolean | 是否监听最近联系人待回复 |
| `autoReply.requirePendingClearForNextRound` | boolean | 是否需待回复清空后才进入下一轮 |
| `autoReply.startChromeDebugIfNeeded` | boolean | 缺少调试浏览器时是否自动启动 |
| `autoReply.statePath` | string | 本地状态文件路径，默认 `./runtime/resident-auto-reply-state.json` |

## 5. 执行结果展示

- 每条流程记录的卡片上展示最近一次执行状态（徽标 + 摘要）。
- 点击卡片或单独的"详情"区域可展开查看：
  - 执行状态（成功 / 失败 / 执行中 / 需人工处理）
  - 最近消息（resultReason / resultSummary）
  - 标准输出（stdout）
  - 标准错误（stderr）
  - 解析后的 JSON 响应

## 6. 导航集成

- **左侧导航栏**：在 MeshCentral 左侧菜单中新增"流程管理"图标按钮，图标 ID 为 `LeftMenuFlowManager`。
- **路由逻辑**：点击图标调用 `go(102)` 函数（使用 `p102` 作为页面 ID，紧接商品管理的 `p101`），在主区域显示流程管理视图。
- **顶部菜单栏**：同步在 `MainMenuSpan` 中添加对应的顶部菜单项 `MainMenuFlowManager`，保持两套导航一致。

## 7. 交互与反馈

- 页面切换时使用**淡入（fade-in）过渡**，保持与 MeshCentral 整体风格协调。
- 所有增删改操作完成后展示**顶部 Toast 轻提示**（成功/失败不同样式）。
- 执行流程时，卡片执行状态区域进入执行中状态并显示加载动画；执行完成后更新最终状态和最近执行时间。
- 空状态、加载中等需要有明确的视觉反馈。

## 8. 技术实现思路

- **HTML/Handlebars**：在 `default.handlebars` 的 `page_leftbar` 添加"流程管理"按钮；在 `column_l` 添加对应的页面容器 `div id=p102`，避免与现有页面 ID 冲突。
- **CSS**：在 `styles/style.css` 中追加，或新建独立 CSS 文件，定义 `.flow-card`、`.flow-btn`、`.flow-toast`、`.flow-empty`、`.flow-status-badge` 等样式类，前缀统一用 `flow-` 避免与现有样式冲突。
- **JavaScript**：在 `scripts/meshcentral.js` 或自定义脚本中添加 `flowManager` 相关逻辑，处理 CRUD 数据流及执行调用。
- **MeshCentral Agent 调用**：
  - 1.0 版本按目标设备系统执行目标设备本地 `ai-bot` 仓库中的脚本入口，不把完整业务脚本内嵌到流程记录。
  - MeshCentral 负责选择目标设备、写入临时配置文件、执行命令、收集 stdout / stderr / exitCode，并在完成后通过 WebSocket 回传结果；后续可扩展实时日志推送。
  - 若后续使用 MeshCentral 脚本库，脚本库中建议只保存轻量 wrapper，用于定位本地 `ai-bot` 仓库并调用下表脚本入口；业务脚本仍以目标设备本地仓库为准。
  - **脚本预置要求**：每台可执行流程的目标设备需预先部署 `ai-bot` 仓库、Python 3.11+、依赖环境、浏览器调试环境和对应平台脚本。

### 8.1 跨平台脚本入口

| 流程类型 | macOS 脚本入口 | macOS 参数 | Windows 脚本入口 | Windows 参数 |
| --- | --- | --- | --- | --- |
| `publish` | `scripts-mac/run-publish-product.sh` | `<configPath>` | `scripts/run-publish-product.ps1` | `-ConfigPath <configPath>` |
| `pricing` | `scripts-mac/run-pricing.sh` | `<configPath>` | `scripts/run-pricing.ps1` | `-ConfigPath <configPath>` |
| `auto_reply` | `scripts-mac/run-resident-auto-reply.sh` | `--config <configPath>`，可选 `--once` | `scripts/run-resident-auto-reply.ps1` | `-ConfigPath <configPath>`，可选 `-Once` |

### 8.2 目标设备运行前置条件

- 目标设备必须已安装 MeshCentral Agent，且 Agent 具备执行本地 shell / PowerShell 命令的权限。
- 目标设备必须能访问本地 `ai-bot` 仓库路径。默认建议 macOS 为 `/Users/<user>/Documents/ai-bot`，Windows 为 `C:\Users\<user>\Documents\ai-bot`，实际路径可在流程记录中覆盖。
- macOS 设备使用 bash 执行 `.sh`，Windows 设备使用 PowerShell 执行 `.ps1`。
- 目标设备需提前完成商家后台 Chrome 调试浏览器登录态准备，脚本默认使用 `9222` 端口和 merchant profile。
- `publish` 和 `pricing` 还依赖 H5 Camoufox 环境；首次执行可能安装或拉取 Camoufox，建议上线前通过环境检查脚本预热。
- `auto_reply` 是常驻流程，默认可能长时间运行。1.0 建议提供“单次执行/常驻执行”开关：调试时使用 `--once` / `-Once`，生产监控时使用常驻模式，并在流程记录中保存运行中的进程标识或会话标识。

### 8.3 数据持久化

对接 MeshCentral 的后端数据库（db.js），流程配置表命名为 `flows`，执行历史表命名为 `flow_runs`。
- `flow_runs` 既用于记录一次性流程执行，也用于记录 `auto_reply` 这类常驻流程的启动、心跳、停止和异常退出信息。

### 8.4 数据表结构建议（flows）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 唯一 ID |
| `name` | string | 流程名称 |
| `flowType` | string | 流程类型：publish / pricing / auto_reply |
| `deviceOs` | string | 目标设备系统：macos / windows |
| `deviceId` | string | 目标设备 MeshCentral Device ID |
| `projectRoot` | string | 目标设备上的 `ai-bot` 仓库路径 |
| `scriptName` | string | 当前流程脚本名称 |
| `scriptEntries` | object | 跨平台脚本入口配置，包含 macos/windows 的脚本路径和参数模板 |
| `config` | object | 流程配置 JSON，对应第 4 节各类型字段；其中 `publish` 在 `products[]` 级别绑定采集数据，`pricing` 可在流程根级别配置 `collectTaskId` 或 `collectResultId` |
| `remark` | string | 备注 |
| `lastRunAt` | date | 最近执行时间 |
| `lastRunStatus` | string | 最近执行存储状态：idle / running / success / failed / manual_required / skipped |
| `lastRunResult` | object | 最近执行结果（stdout、stderr、exitCode 等） |
| `activeRunId` | string\|null | 当前运行中的 `flow_runs._id`；仅常驻流程运行中时有值 |
| `createdAt` | date | 创建时间 |
| `updatedAt` | date | 更新时间 |

### 8.5 执行历史表结构建议（flow_runs）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 唯一 ID |
| `flowId` | string | 关联流程 ID（`flows._id`） |
| `flowType` | string | 流程类型：publish / pricing / auto_reply |
| `collectBindings` | array\|null | 本次执行使用的采集绑定明细。`publish` 按商品项记录 `productKey / collectTaskId / collectResultId`；`pricing` 记录单条流程级绑定；`auto_reply` 为 null |
| `scriptName` | string | 脚本名称 |
| `scriptPath` | string | 本次执行使用的目标设备脚本路径 |
| `arguments` | array | 本次执行参数，包含临时配置路径等 |
| `deviceId` | string | 目标设备 MeshCentral Device ID |
| `deviceOs` | string | 目标设备系统：macos / windows |
| `status` | string | 执行存储状态：running / success / failed / manual_required / skipped |
| `stdout` | string | 脚本标准输出 |
| `stderr` | string | 脚本标准错误 |
| `exitCode` | number\|null | 脚本退出码 |
| `resultSummary` | string | 执行摘要 |
| `resultJson` | object\|null | 解析后的 JSON 响应 |
| `sessionId` | string\|null | MeshCentral 或业务侧生成的运行会话 ID，常驻流程优先使用 |
| `processId` | string\|null | 目标设备上的进程 ID，适用于停止运行中流程 |
| `lastHeartbeatAt` | date\|null | 常驻流程最近一次心跳时间 |
| `startedAt` | date | 开始时间 |
| `finishedAt` | date\|null | 结束时间 |

## 9. 已确认与待确认问题

1. **MeshCentral Agent 接口**：具体调用哪个 MeshCentral 内部接口触发设备脚本执行？建议优先复用 `meshcentral.js` 中已有的设备命令执行能力。
2. **脚本管理**：已统一为跨平台本地脚本入口方案。macOS 默认调用 `scripts-mac/*.sh`，Windows 默认调用 `scripts/*.ps1`；MeshCentral 脚本库若使用，仅保存轻量 wrapper，不保存完整业务脚本。
3. **执行结果推送**：已统一为 1.0 通过 MeshCentral WebSocket 完成后回传；实时日志后续增强。
4. **权限控制**：哪些级别的用户可以看到并操作"流程管理"？默认所有用户可见。
5. **移动端适配**：当前仓库未发现 `views/default-mobile.handlebars`，1.0 先在 `default.handlebars` 中做响应式适配；若后续恢复移动端模板，再同步添加流程管理入口。
6. **多设备并发执行**：同一流程是否支持同时向多个设备下发执行？1.0 版本建议每次只选一个设备。
