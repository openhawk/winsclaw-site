# 流程管理需求 1.0

## 1. 项目背景

在 MeshCentral 管理系统中集成流程管理功能，旨在提供一个统一的入口，对 OpenClaw 控制台中已有的 3 个自动化流程进行增删改查管理，并支持通过 MeshCentral 的 Agent 能力对指定设备远程执行流程内的脚本和命令。

**与采集管理的关系**：流程管理与采集管理是并列的功能模块。商品发布流程（publish）和调价流程（pricing）在执行时，依赖采集管理预先从美团外卖 H5 采集并存入数据库的数据；若数据库中无对应有效采集数据，则不允许触发这两个流程的同步执行（执行按钮禁用）。自动回复监控流程（auto_reply）无此依赖，可直接执行。

当前 3 个流程来自 `aibot/web/index.html`（OpenClaw 控制台），分别为：

| 流程 ID | 流程名称 | 说明 |
| --- | --- | --- |
| `publish` | 商品发布流程 | 读取采集管理已采集的店铺商品数据，同步发布到美团商家后台 |
| `pricing` | 调价流程 | 读取采集管理已采集的竞品价格数据，自动对目标商品改价 |
| `auto_reply` | 自动回复监控流程 | 常驻监控美团 IM 工作台并自动回复买家消息 |

## 2. 界面设计要求

- **风格参考**：与店铺管理、商品管理页面保持一致，采用与 MeshCentral 管理后台相协调的克制风格。
- **视觉特点**：
  - 采用卡片式布局展示流程列表。
  - 响应式设计，优先适配桌面端浏览器，兼顾移动端。
  - 图标使用简洁明快的风格。

## 3. 功能需求

### 3.1 流程列表 (Read)

- 展示所有已保存到数据库的流程记录。
- 每条记录卡片展示：流程名称、流程类型（publish / pricing / auto_reply）、关联脚本名称、目标设备、上次执行时间、执行状态。
- 支持按流程名称模糊搜索。
- 流程数量较多时支持分页展示（每页默认 10 条）。
- 列表为空时展示友好的空状态提示（如"暂无流程，点击右上角添加"）。
- 每条记录提供**编辑**和**执行**两个操作按钮。

### 3.2 添加流程 (Create)

- 提供"新增流程"按钮（页面右上角）。
- 输入项：
  - **流程名称**：用户自定义名称，必填。
  - **流程类型**：下拉选择 `publish`（商品发布）/ `pricing`（调价）/ `auto_reply`（自动回复），必填。
  - **关联脚本**：从 MeshCentral 脚本库中选择要执行的脚本（下拉列表动态拉取脚本库已有脚本），必填。三个流程对应的脚本需提前在 MeshCentral 脚本库中上传并命名：`run-publish-product.ps1`（商品发布）、`run-pricing.ps1`（调价）、`run-auto-reply.ps1`（自动回复）。
  - **目标设备**：选择已在 MeshCentral 注册的设备（Agent），必填。
  - **流程配置（JSON）**：对应流程类型的完整配置内容（见第 4 节），选填，留空时使用默认配置。
  - **备注**：选填。
- 提交校验：流程名称、流程类型、关联脚本、目标设备为必填，其余选填。
- 提交成功/失败后展示 Toast 轻提示。

### 3.3 编辑流程 (Update)

- 列表卡片操作区提供"编辑"按钮，点击后弹出全屏或居中弹窗表单进行修改。
- 编辑弹窗复用新增表单，字段预填入当前流程数据。
- 流程配置（JSON）以可编辑文本域展示，支持直接修改。
- 保存成功/失败后展示 Toast 轻提示。

### 3.4 删除流程 (Delete)

- 列表卡片操作区提供"删除"按钮（与编辑按钮并列）。
- 点击删除后弹出确认弹窗，防止误操作。
- 确认删除后列表自动刷新，并展示 Toast 轻提示。

### 3.5 执行流程

- 每条流程记录提供"执行"按钮。
- **前置数据检查**（仅 publish 和 pricing 流程）：点击"执行"前，系统自动检查 `openclaw_collect_results` 表中是否存在对应类型（`collect_shop` / `collect_price`）且状态为 `success` 的有效采集数据（默认有效期 24 小时）。若无有效数据，"执行"按钮禁用，并展示提示（如"请先在采集管理中完成店铺信息采集"/ "请先在采集管理中完成价格信息采集"）。`auto_reply` 流程无此检查，可直接执行。
- 点击执行后，系统通过 MeshCentral 的 Agent 能力，向已选目标设备下发流程内关联的脚本和命令，远程执行。
- 执行触发逻辑：
  1. 读取该流程记录的配置（流程类型、关联脚本、目标设备、流程配置 JSON）。
  2. 对于 publish 流程：从 `openclaw_collect_results` 读取最新的 `collect_shop` 数据作为商品数据源，传入执行脚本。
  3. 对于 pricing 流程：从 `openclaw_collect_results` 读取最新的 `collect_price` 数据作为竞品价格参考，传入执行脚本。
  4. 调用 MeshCentral 的设备脚本执行接口，**通过脚本库脚本 ID** 触发执行（不内嵌脚本内容），由 MeshCentral 从脚本库取出对应脚本下发到目标设备上的 Agent。
  5. Agent 在目标设备上运行对应脚本（`run-publish-product.ps1`、`run-pricing.ps1`、`run-auto-reply.ps1`），脚本内容以 MeshCentral 脚本库为准，流程记录中仅保存脚本 ID 和脚本名称。
  6. 执行结果（stdout、stderr、退出码、状态）实时或完成后回传，展示在卡片的执行状态区域；执行记录中写入所引用的采集结果 `_id`，便于追溯数据来源。
- 执行状态可选值：空闲 / 执行中 / 成功 / 失败 / 需人工处理 / 已跳过。
- 执行期间"执行"按钮禁用，防止重复触发。

## 4. 流程类型与配置字段说明

### 4.1 商品发布流程（publish）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市，例如"苏州市" |
| `myLocationAddress` | string | 定位地址，例如"相城区黄埭实验小学" |
| `products` | array | 商品条目列表 |
| `products[].key` | string | 商品节点唯一标识，用于图片命名和日志 |
| `products[].shopName` | string | 来源店铺名称 |
| `products[].productName` | string | 来源商品名称或关键词 |
| `products[].fetchFromH5` | boolean | 是否先从 H5 抓取再发布 |
| `products[].enabled` | boolean | 是否启用，默认 true |
| `products[].overwritePolicy` | string | 覆盖策略：overwrite / merge / skipIfExists |
| `products[].requiredAttributeMappings` | array | 属性值映射规则，每条含 label、from、to |

### 4.2 调价流程（pricing）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市 |
| `myLocationAddress` | string | 定位地址 |
| `globalEnabled` | boolean | 全局开关，是否启用全部调价任务 |
| `tasks` | array | 调价任务列表 |
| `tasks[].taskId` | string | 任务唯一标识 |
| `tasks[].enabled` | boolean | 任务是否启用 |
| `tasks[].targetProductName` | string | 目标商品名称 |
| `tasks[].referenceKeyword` | string | 参考商品关键词 |
| `tasks[].referenceShops` | array | 参考店铺列表（每行一个店铺名） |
| `tasks[].referenceProductSelection` | string | 参考商品选择：first / lowest / highest / average |
| `tasks[].strategy` | string | 调价策略：average / max / min / fixed |
| `tasks[].priceOffset` | number | 价格偏移量 |
| `tasks[].fixedPrice` | number\|null | 固定价格，空时按策略计算 |
| `tasks[].duplicateTargetPolicy` | string | 重复商品处理：fail / first |
| `tasks[].skuStrategy` | string | SKU 策略：allActive / first / mainOnly |
| `tasks[].priceLimit.min` | number\|null | 最低限价 |
| `tasks[].priceLimit.max` | number\|null | 最高限价 |

### 4.3 自动回复监控流程（auto_reply）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `autoReply.enabled` | boolean | 是否启用监控 |
| `autoReply.replyText` | string | 固定回复文本，例如"您好" |
| `autoReply.pollIntervalSeconds` | number | 轮询间隔（秒），默认 3 |
| `autoReply.maxRetries` | number | 最大重试次数，默认 3 |
| `autoReply.cdpUrl` | string | Chrome CDP 地址，默认 `http://127.0.0.1:9222` |
| `autoReply.preferredUrl` | string | 优先跳转的 IM 工作台页面 URL |
| `autoReply.fallbackOpenUrl` | string | 备用打开地址 |
| `autoReply.monitorRecentContacts` | boolean | 是否监听最近联系人待回复 |
| `autoReply.requirePendingClearForNextRound` | boolean | 是否需待回复清空后才进入下一轮 |
| `autoReply.startChromeDebugIfNeeded` | boolean | 缺少调试浏览器时是否自动启动 |
| `autoReply.statePath` | string | 本地状态文件路径，默认 `./runtime/resident-auto-reply-state.json` |

## 5. 执行结果展示

- 每条流程记录的卡片上展示最近一次执行状态（徽标 + 摘要）。
- 点击卡片或单独的"详情"区域可展开查看：
  - 执行状态（成功 / 失败 / 执行中 / 需人工处理）
  - 最近消息（resultReason / resultSummary）
  - 标准输出（stdout）
  - 标准错误（stderr）
  - 解析后的 JSON 响应

## 6. 导航集成

- **左侧导航栏**：在 MeshCentral 左侧菜单中新增"流程管理"图标按钮，使用 **den** 作为导航标识，图标 ID 为 `LeftMenuFlowManager`。
- **路由逻辑**：点击图标调用 `go(102)` 函数（使用 `p102` 作为页面 ID，紧接商品管理的 `p101`），在主区域显示流程管理视图。
- **顶部菜单栏**：同步在 `MainMenuSpan` 中添加对应的顶部菜单项 `MainMenuFlowManager`，保持两套导航一致。

## 7. 交互与反馈

- 页面切换时使用**淡入（fade-in）过渡**，保持与 MeshCentral 整体风格协调。
- 所有增删改操作完成后展示**顶部 Toast 轻提示**（成功/失败不同样式）。
- 执行流程时，卡片执行状态区域实时更新，执行中显示加载动画。
- 空状态、加载中等需要有明确的视觉反馈。

## 8. 技术实现思路

- **HTML/Handlebars**：在 `default.handlebars` 的 `page_leftbar` 添加"流程管理"按钮（den 导航）；在 `column_l` 添加对应的页面容器 `div id=p102`，避免与现有页面 ID 冲突。
- **CSS**：在 `styles/style.css` 中追加，或新建独立 CSS 文件，定义 `.flow-card`、`.flow-btn`、`.flow-toast`、`.flow-empty`、`.flow-status-badge` 等样式类，前缀统一用 `flow-` 避免与现有样式冲突。
- **JavaScript**：在 `scripts/meshcentral.js` 或自定义脚本中添加 `flowManager` 相关逻辑，处理 CRUD 数据流及执行调用。
- **MeshCentral Agent 调用**：
  - 脚本统一在 MeshCentral 脚本库中管理，流程记录中仅存储脚本库的脚本 ID（`scriptId`）和脚本名称（`scriptName`），不内嵌脚本内容。
  - 执行时调用 MeshCentral 的设备脚本执行 API，传入脚本 ID 和目标设备 ID，由 MeshCentral 从脚本库取出脚本后下发至 Agent 运行。
  - 流程配置 JSON 作为脚本运行参数或临时配置文件传入 Agent。
  - 执行结果通过 MeshCentral WebSocket 或轮询接口回传。
  - **脚本预置要求**：系统上线前，运维人员须在 MeshCentral 后台「脚本库」中预先上传以下 3 个 PowerShell 脚本：
    | 脚本文件名 | 对应流程 |
    | --- | --- |
    | `run-publish-product.ps1` | 商品发布流程（publish） |
    | `run-pricing.ps1` | 调价流程（pricing） |
    | `run-auto-reply.ps1` | 自动回复监控流程（auto_reply） |
- **数据持久化**：对接 MeshCentral 的后端数据库（db.js），数据表建议命名为 `openclaw_flows`，存储流程记录。

### 8.1 数据表结构建议（openclaw_flows）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 唯一 ID |
| `name` | string | 流程名称 |
| `flowType` | string | 流程类型：publish / pricing / auto_reply |
| `scriptId` | string | MeshCentral 脚本库中的脚本 ID（唯一标识） |
| `scriptName` | string | 脚本名称（冗余存储，便于展示，以脚本库为准） |
| `deviceId` | string | 目标设备 MeshCentral Device ID |
| `config` | object | 流程配置 JSON，对应第 4 节各类型字段 |
| `remark` | string | 备注 |
| `lastRunAt` | date | 最近执行时间 |
| `lastRunStatus` | string | 最近执行状态 |
| `lastRunResult` | object | 最近执行结果（stdout、stderr、exitCode 等） |
| `createdAt` | date | 创建时间 |
| `updatedAt` | date | 更新时间 |
