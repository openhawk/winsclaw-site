# 采集管理需求 1.0

## 1. 项目背景

在 MeshCentral 管理系统中集成采集管理功能，与流程管理并列，作为商品发布流程和调价流程的数据来源。

**核心定位**：采集管理负责通过 MeshCentral 的 Agent 能力驱动目标设备上的脚本，从美团外卖 H5 页面采集原始数据（店铺商品信息、竞品价格信息），并将采集结果持久化到数据库。流程管理中的商品发布流程和调价流程在执行时，直接读取数据库中已采集的数据，而非在执行时实时抓取 H5，若数据库中无对应采集数据则不允许执行同步。

当前支持两类采集流程：

| 采集类型 ID | 采集名称 | 说明 | 供给流程 |
| --- | --- | --- | --- |
| `collect_shop` | 店铺信息采集 | 从美团外卖 H5 采集店铺商品列表、价格、规格、属性等信息 | 商品发布流程（publish） |
| `collect_price` | 价格信息采集 | 从美团外卖 H5 采集竞品店铺的商品价格信息 | 调价流程（pricing） |

## 2. 界面设计要求

- **风格参考**：与店铺管理、商品管理、流程管理页面保持一致，采用与 MeshCentral 管理后台相协调的克制风格。
- **视觉特点**：
  - 采用卡片式布局展示采集任务列表。
  - 响应式设计，优先适配桌面端浏览器，兼顾移动端。
  - 图标使用简洁明快的风格。
  - 采集状态使用徽标（badge）高亮展示，便于快速识别采集进度。

## 3. 功能需求

### 3.1 采集任务列表 (Read)

- 展示所有已保存到数据库的采集任务记录。
- 每条记录卡片展示：任务名称、采集类型（collect_shop / collect_price）、目标设备、目标设备系统（macOS / Windows）、当前平台脚本入口、上次采集时间、采集状态、采集到的数据条数。
- 支持按任务名称模糊搜索。
- 任务数量较多时支持分页展示（每页默认 10 条）。
- 列表为空时展示友好的空状态提示（如"暂无采集任务，点击右上角添加"）。
- 每条记录提供**编辑**、**删除**、**执行采集**和**查看采集结果**四个操作按钮。

### 3.2 添加采集任务 (Create)

- 提供"新增采集任务"按钮（页面右上角）。
- 输入项：
  - **任务名称**：用户自定义名称，必填。
  - **采集类型**：下拉选择 `collect_shop`（店铺信息采集）/ `collect_price`（价格信息采集），必填。
  - **目标设备**：选择已在 MeshCentral 注册的设备（Agent），必填；系统根据设备信息识别目标系统类型（macOS / Windows），无法识别时需人工选择。
  - **脚本入口配置**：按采集类型配置 macOS / Windows 两套脚本入口。1.0 版本执行目标设备本地 `ai-bot` 仓库中的采集脚本；若后续使用 MeshCentral 脚本库，脚本库仅保存轻量 wrapper。
  - **采集配置（JSON）**：对应采集类型的完整配置内容（见第 4 节），选填，留空时使用默认配置。
  - **备注**：选填。
- 提交校验：任务名称、采集类型、目标设备、目标设备系统、对应平台脚本入口为必填，其余选填。
- 提交成功/失败后展示 Toast 轻提示。

### 3.3 编辑采集任务 (Update)

- 列表卡片操作区提供"编辑"按钮，点击后弹出全屏或居中弹窗表单进行修改。
- 编辑弹窗复用新增表单，字段预填入当前任务数据。
- 采集配置（JSON）以可编辑文本域展示，支持直接修改。
- 保存成功/失败后展示 Toast 轻提示。

### 3.4 删除采集任务 (Delete)

- 列表卡片操作区提供"删除"按钮（与编辑按钮并列）。
- 点击删除后弹出确认弹窗，防止误操作。
- 删除采集任务时，默认保留该任务已采集的结果数据，便于流程执行记录追溯；确认弹窗中提供"同时清除采集结果"选项，用户勾选后才删除对应 `openclaw_collect_results` 数据。
- 确认删除后列表自动刷新，并展示 Toast 轻提示。

### 3.5 执行采集

- 每条采集任务提供"执行采集"按钮。
- 点击后，系统通过 MeshCentral 的 Agent 能力，在已选目标设备上执行对应平台的本地采集脚本入口，远程执行 H5 数据采集。
- 执行触发逻辑：
  1. 读取该任务记录的配置（采集类型、目标设备、目标设备系统、对应平台脚本入口、采集配置 JSON）。
  2. MeshCentral 服务端将最终采集配置 JSON 写入目标设备临时配置文件，或上传到目标设备指定临时目录。
  3. 调用 MeshCentral Agent 的命令执行能力，在目标设备上运行与系统匹配的采集脚本入口，并把临时配置文件路径作为参数传入。
  4. Agent 在目标设备上执行本地 `ai-bot` 仓库中的采集脚本，驱动本地浏览器访问 H5 并采集数据。
  5. 脚本将采集到的结构化数据（JSON）输出到 stdout 或本地结果文件，由 MeshCentral 服务端接收结果并写入 `openclaw_collect_results` 表；目标设备脚本不直接持有数据库连接信息。
  6. 执行结果（stdout、stderr、退出码、状态、数据条数）完成后回传，展示在卡片的采集状态区域；1.0 版本以完成后更新为准，实时日志可作为后续增强。
- 采集 UI 状态可选值：空闲 / 采集中 / 成功 / 失败 / 需人工处理 / 已跳过。
- 采集存储状态可选值：idle / running / success / failed / manual_required / skipped / partial。前端展示时映射为对应中文状态。
- 采集期间"执行采集"按钮禁用，防止重复触发。

### 3.6 查看采集结果

- 每条采集任务提供"查看采集结果"按钮（或点击卡片展开详情）。
- 展示本次及历史采集到的数据预览：
  - **店铺信息采集**：展示采集到的商品列表（名称、价格、规格、属性等字段预览）。
  - **价格信息采集**：展示采集到的竞品价格列表（店铺名称、商品名称、价格等）。
- 支持查看原始 JSON 数据（折叠/展开）。
- 展示采集时间戳和数据条数。

## 4. 采集类型与配置字段说明

### 4.1 店铺信息采集（collect_shop）

从美团外卖 H5 页面采集目标店铺的商品列表及详情，数据供商品发布流程使用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市，例如"苏州市" |
| `myLocationAddress` | string | 定位地址，例如"相城区黄埭实验小学" |
| `targetShops` | array | 要采集的目标店铺列表 |
| `targetShops[].shopName` | string | 目标店铺名称（H5 搜索关键词） |
| `targetShops[].productKeyword` | string | 商品筛选关键词，为空时采集全部商品 |
| `targetShops[].enabled` | boolean | 是否启用该店铺采集，默认 true |
| `outputPath` | string | 采集结果本地输出路径（Agent 本地），例如 `./collect-results/shop/` |
| `saveToDb` | boolean | 是否同步写入服务端数据库，1.0 固定为 true；若后续允许 false，则该采集结果不能作为流程数据源 |

### 4.2 价格信息采集（collect_price）

从美团外卖 H5 页面采集竞品店铺的商品价格信息，数据供调价流程使用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 定位城市 |
| `myLocationAddress` | string | 定位地址 |
| `priceTasks` | array | 价格采集任务列表 |
| `priceTasks[].taskId` | string | 任务唯一标识 |
| `priceTasks[].enabled` | boolean | 是否启用，默认 true |
| `priceTasks[].referenceKeyword` | string | 竞品搜索关键词 |
| `priceTasks[].referenceShops` | array | 要采集的竞品店铺名称列表 |
| `priceTasks[].referenceProductSelection` | string | 参考商品选择：first / lowest / highest / average |
| `outputPath` | string | 采集结果本地输出路径（Agent 本地），例如 `./collect-results/price/` |
| `saveToDb` | boolean | 是否同步写入服务端数据库，1.0 固定为 true；若后续允许 false，则该采集结果不能作为流程数据源 |

## 5. 采集结果数据库结构

采集结果写入 `openclaw_collect_results` 表，供流程管理中的流程执行时读取。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 唯一 ID |
| `taskId` | string | 关联的采集任务 ID（`openclaw_collect_tasks._id`） |
| `collectType` | string | 采集类型：collect_shop / collect_price |
| `data` | array | 采集到的结构化数据（JSON 数组） |
| `dataCount` | number | 采集到的数据条数 |
| `collectedAt` | date | 采集时间 |
| `deviceId` | string | 执行采集的设备 MeshCentral Device ID |
| `status` | string | 采集存储状态：idle / running / success / failed / manual_required / skipped / partial |
| `stdout` | string | 脚本标准输出 |
| `stderr` | string | 脚本标准错误 |

## 6. 与流程管理的数据关联

- **商品发布流程（publish）** 在执行前，系统自动检查 `openclaw_collect_results` 表中是否存在类型为 `collect_shop` 且状态为 `success` 的有效采集数据（时间在有效期内，默认 24 小时内）。若无，则禁用"执行"按钮并提示"请先在采集管理中完成店铺信息采集"。
- **调价流程（pricing）** 在执行前，系统自动检查 `openclaw_collect_results` 表中是否存在类型为 `collect_price` 且状态为 `success` 的有效采集数据（时间在有效期内，默认 24 小时内）。若无，则禁用"执行"按钮并提示"请先在采集管理中完成价格信息采集"。
- 采集结果匹配优先级：流程记录中若配置了 `collectTaskId`，则读取该任务下最新有效结果；若配置了 `collectResultId`，则读取指定结果并校验类型、状态和有效期；若两者都未配置，则按 `collectType` 读取最新有效结果。推荐 1.0 在流程配置中显式保存 `collectTaskId`，避免多店铺、多设备场景下误用数据。
- 流程执行时将对应采集结果的 `_id` 写入流程执行记录，便于追溯数据来源。

## 8. 交互与反馈

- 页面切换时使用**淡入（fade-in）过渡**，保持与 MeshCentral 整体风格协调。
- 所有增删改操作完成后展示**顶部 Toast 轻提示**（成功/失败不同样式）。
- 采集执行时，卡片采集状态区域进入采集中状态并显示加载动画；采集完成后更新最终状态、数据条数和最近采集时间。
- 空状态、加载中等需要有明确的视觉反馈。

## 9. 技术实现思路

- **HTML/Handlebars**：在 `default.handlebars` 的 `page_leftbar` 添加"采集管理"按钮；在 `column_l` 添加对应的页面容器 `div id=p103`，避免与现有页面 ID 冲突。
- **CSS**：定义 `.collect-card`、`.collect-btn`、`.collect-toast`、`.collect-empty`、`.collect-status-badge`、`.collect-data-preview` 等样式类，前缀统一用 `collect-` 避免与现有样式冲突。
- **JavaScript**：在自定义脚本中添加 `collectManager` 相关逻辑，处理 CRUD 数据流及采集执行调用。
- **MeshCentral Agent 调用**：1.0 版本按目标设备系统执行目标设备本地 `ai-bot` 仓库中的采集脚本入口，不把完整业务脚本内嵌到采集任务记录。MeshCentral 负责选择目标设备、写入临时配置文件、执行命令、收集 stdout / stderr / exitCode，并在完成后通过 WebSocket 回传结果。若后续使用 MeshCentral 脚本库，脚本库中建议只保存轻量 wrapper，用于定位本地 `ai-bot` 仓库并调用对应平台脚本入口。
- **数据持久化**：
  - 采集任务表：`openclaw_collect_tasks`，存储任务配置记录。
  - 采集结果表：`openclaw_collect_results`，存储每次采集的数据结果。

### 9.1 采集任务数据表结构（openclaw_collect_tasks）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 唯一 ID |
| `name` | string | 任务名称 |
| `collectType` | string | 采集类型：collect_shop / collect_price |
| `deviceOs` | string | 目标设备系统：macos / windows |
| `deviceId` | string | 目标设备 MeshCentral Device ID |
| `projectRoot` | string | 目标设备上的 `ai-bot` 仓库路径 |
| `scriptName` | string | 当前采集脚本名称 |
| `scriptEntries` | object | 跨平台脚本入口配置，包含 macos/windows 的脚本路径和参数模板 |
| `config` | object | 采集配置 JSON，对应第 4 节各类型字段 |
| `remark` | string | 备注 |
| `lastRunAt` | date | 最近采集时间 |
| `lastRunStatus` | string | 最近采集存储状态：idle / running / success / failed / manual_required / skipped / partial |
| `lastDataCount` | number | 最近一次采集到的数据条数 |
| `createdAt` | date | 创建时间 |
| `updatedAt` | date | 更新时间 |

### 9.2 采集结果保留策略

- 同一采集任务多次执行时，`openclaw_collect_results` 默认追加历史记录。
- 每个采集任务默认保留最近 10 条结果，超出后可由后台清理任务清除更早记录。
- `openclaw_collect_tasks.lastRunAt`、`lastRunStatus`、`lastDataCount` 始终冗余保存最近一次执行摘要，用于列表快速展示。

## 10. 已确认与待确认问题

1. **采集有效期**：已统一为默认 24 小时，超时后流程管理中对应执行按钮自动禁用并提示重新采集。
2. **多次采集覆盖策略**：已统一为追加历史记录，并默认保留每个任务最近 10 条。
3. **采集脚本管理**：已统一为跨平台本地脚本入口方案。macOS 调用 `.sh`，Windows 调用 `.ps1`；MeshCentral 脚本库若使用，仅保存轻量 wrapper，不保存完整业务脚本。
4. **权限控制**：哪些级别的用户可以看到并操作"采集管理"？默认所有用户可见。
5. **移动端适配**：当前仓库未发现 `views/default-mobile.handlebars`，1.0 先在 `default.handlebars` 中做响应式适配；若后续恢复移动端模板，再同步添加采集管理入口。
6. **采集数据预览**：采集结果数据量较大时，是否支持分页展示或搜索过滤？1.0 版本建议展示前 20 条并提供"查看全部"入口。
