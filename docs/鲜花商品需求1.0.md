# 鲜花商品上架管理需求 1.0

## 1. 项目背景
在 MeshCentral 管理系统中集成鲜花商品上架管理功能，旨在提供一个直观、易用的商品信息维护界面，支持对鲜花商品进行增删改查，并与美团外卖商家后台上架流程对接。

## 2. 界面设计要求
- **风格参考**：与店铺管理页面保持一致，采用美团 H5 页面风格，适配桌面端管理系统的实际使用场景。
- **视觉特点**：
  - 采用卡片式布局展现商品列表。
  - 使用美团标志性的黄色 (#FFD000) 作为主色调点缀，整体保持与 MeshCentral 管理后台相协调的克制风格。
  - 响应式设计，优先适配桌面端浏览器，兼顾移动端。
  - 图标使用简洁明快的风格。

## 3. 功能需求

### 3.1 商品列表 (Read)
- 展示所有已登记的鲜花商品。
- 每项卡片展示：商品主图、商品名称、活动价、划线价、规格数量、所属店铺、店内分类、库存。
- 支持按商品名称模糊搜索。
- 商品数量较多时支持分页展示（每页默认 10 条）。
- 列表为空时展示友好的空状态提示（如"暂无商品，点击右上角添加"）。
- 支持点击卡片进入详情查看（可折叠在编辑弹窗中实现）。

### 3.2 添加商品 (Create)
- 提供"新增商品"按钮（页面右上角）。
- 输入项：
  - **基本信息**：商品名称、所属店铺、店内分类（`storeCategoryPath`）、商品描述（`description`）。
  - **价格与库存**：活动价（`price`）、划线价（`originalPrice`）、库存（`inventory`，默认 1）。
  - **类目**：类目路径（`categoryPath`，默认"花草园艺 > 礼品花 > 礼品鲜花"）。
  - **规格**：默认规格（`sku`）；支持多规格列表（`skuList`），每条规格包含规格名称/值、活动价、划线价、库存。
  - **必填属性**（`requiredAttributes`）：主花材、色系、适用人群。
  - **图片**：商品主图路径（`imagePaths`）、图片 URL（`imageUrls`，选填）。
  - **发布配置**：商家后台入口 URL（`entryUrl`）、是否仅使用已有选项（`useExistingOptionsOnly`，默认 `true`）。
- 提交校验：商品名称、活动价、所属店铺、店内分类、主花材、色系、适用人群为必填，其余选填。
- 提交成功/失败后展示 Toast 轻提示。

### 3.3 编辑商品 (Update)
- 列表卡片操作区提供"编辑"按钮，点击后弹出全屏或居中弹窗表单进行修改。
- 编辑弹窗复用新增表单，字段预填入当前商品数据。
- 多规格（`skuList`）支持在弹窗内动态增减规格行。
- 保存成功/失败后展示 Toast 轻提示。

### 3.4 删除商品 (Delete)
- 列表卡片操作区提供"删除"按钮（与编辑按钮并列）。
- 点击删除后弹出确认弹窗，防止误操作。
- 确认删除后列表自动刷新，并展示 Toast 轻提示。

## 4. 商品字段说明

| 字段 | 说明 | 是否必填 | 默认值 |
| --- | --- | --- | --- |
| `name` | 商品名称，超过后台长度限制时截断并记录 warning | 必填 | — |
| `price` | 活动价，多规格时写最低活动价 | 必填 | — |
| `originalPrice` | 划线价，无则为 `null` | 选填 | `null` |
| `description` | 商品详情描述，无则写"上架商品" | 选填 | `"上架商品"` |
| `imagePaths` | 主图本地路径，格式：`./publish-images/{key}-main.{ext}` | 必填 | — |
| `imageUrls` | 主图原始 URL，调试用 | 选填 | `[]` |
| `sku` | 默认规格或第一个规格组合 | 必填 | `[{"name":"规格","value":"默认规格"}]` |
| `skuList` | 全部规格列表，每项含 specs、price、originalPrice、inventory | 选填 | — |
| `inventory` | 库存，每个规格默认 1 | 选填 | `1` |
| `categoryPath` | 类目路径 | 必填 | `["花草园艺","礼品花","礼品鲜花"]` |
| `storeCategoryPath` | 店内分类，从 H5 抓取 | 必填 | — |
| `requiredAttributes` | 必填属性：主花材、色系、适用人群 | 必填 | — |
| `useExistingOptionsOnly` | 是否仅使用已有选项 | 选填 | `true` |
| `entryUrl` | 商家后台发布入口 URL | 选填 | — |

### 4.1 多规格数据结构（`skuList`）

## 5. 导航集成
- **左侧导航栏**：在"店铺管理"图标按钮之后增加"商品管理"图标按钮。
- **图标 ID**：`LeftMenuProductManager`。
- **路由逻辑**：点击图标调用 `go(101)` 函数（使用 `p101` 作为页面 ID，紧接店铺管理的 `p100`），在主区域显示商品管理视图。
- **顶部菜单栏**：同步在 `MainMenuSpan` 中添加对应的顶部菜单项 `MainMenuProductManager`，保持两套导航一致。

## 6. 交互与反馈
- 页面切换时使用**淡入（fade-in）过渡**，保持与 MeshCentral 整体风格协调，不使用涟漪等移动端专属动效。
- 所有增删改操作完成后展示**顶部 Toast 轻提示**（成功/失败不同样式）。
- 空状态、加载中等需要有明确的视觉反馈。
- 多规格列表支持动态增减行，行内字段实时校验。

## 7. 技术实现思路
- **HTML/Handlebars**：在 `default.handlebars` 的 `page_leftbar` 添加按钮；在 `column_l` 添加对应的页面容器 `div id=p101`，避免与现有页面 ID 冲突。
- **CSS**：在 `styles/style.css` 中追加，或新建独立 CSS 文件，定义 `.product-card`、`.product-btn`、`.product-toast`、`.product-empty`、`.product-sku-row` 等样式类，前缀统一用 `product-` 避免与现有样式冲突。
- **JavaScript**：在 `scripts/meshcentral.js` 或自定义脚本中添加 `productManager` 相关逻辑，处理 CRUD 数据流及多规格动态表单。
